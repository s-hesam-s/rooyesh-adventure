# راهنمای توسعه نسخه ماجراجویی

## معماری

داستان یک گراف جهت‌دار است؛ nodeId مکان فعلی را مشخص می‌کند. هر exit به شناسه ناحیه بعد وصل است. engine به Canvas، DOM، localStorage یا HTTP وابسته نیست. Renderer بازی را نقاشی می‌کند و state را تغییر نمی‌دهد. main ورودی را به حرکت یا رویداد دامنه تبدیل می‌کند.

هر انتخاب یک رویداد travel، هر بررسی یک inspect و هر برخورد یک collision می‌سازد. ذخیره با replay همین رویدادها بازسازی می‌شود. اطلاعات خام trust، inventory یا ending در فایل ذخیره مرجع نیستند. این بازسازی برای سازگاری است، نه امنیت ارزیابی رسمی.

## ناحیه تازه

در story.js یک node با شناسه پایدار اضافه کنید:

```js
'new-area': {
  title: 'نام ناحیه',
  area: 'نام بخش',
  theme: 'garden',
  objective: 'هدف کوتاه',
  objects: [
    item('document', 'نام میز', 'متن بررسی', {
      kind: 'book',
      grant: 'archive'
    })
  ],
  exits: [
    gate('forward', 'نام راه اول', 'next-node', {
      requires: 'archive',
      cost: 6,
      detail: 'توضیح راه'
    }),
    gate('other', 'نام راه دوم', 'other-node', { cost: 8 })
  ]
}
```

قالب فعلی ۲ یا ۳ دروازه و حداکثر دو جایگاه شیء دارد. افزودن بیش از دو شیء نیاز به گسترش layoutFor دارد تا مختصات تکراری نشوند. میدان راه، برخورد و مسیریابی از یک مجموعه polyline استفاده می‌کنند؛ بنابراین ظاهر راه و منطق عبور جدا از هم منحرف نمی‌شوند.

theme می‌تواند garden، glass، court، water یا hill باشد. برای هندسه متفاوت، layoutFor در world.js را توسعه دهید. افزودن theme تنها شکل محیط را عوض می‌کند؛ شاخه داستان را باید با exit.next تعریف کنید.

## مدرک و دروازه

مدرک در items تعریف می‌شود. شیء grant همان شناسه را می‌دهد. requires روی دروازه یک شناسه یا آرایه شناسه‌ها می‌پذیرد. گرفتن دوباره مدرک اثر تکراری ندارد.

برخورد با درِ قفل‌شده نه هزینه سفر کم می‌کند و نه به ناحیه بعد می‌رود. دروازه حدود ۰.۶۵ ثانیه حضور در شعاع ورود می‌خواهد؛ خروج از شعاع آن را لغو می‌کند.

گزینه back در node یک مسیر بازگشت فیزیکی پایین سمت راست می‌سازد. در این نسخه برای برگشت از ظرفیت به دفتر هویت استفاده شده است.

## پایان

node پایان فقط ending دارد. متن، نوع good/warm/sad و صحنه پایانی در endings و endingScenes تعیین می‌شوند. پایان‌های bloom و keeper در صورت داشتن پرچم recovered به پایان ترمیم تبدیل می‌شوند. اتمام فرصت، مستقل از گره فعلی، پایان timeout می‌سازد.

همه راه‌ها باید cost مثبت داشته باشند؛ این موضوع از حلقه بی‌پایان منطقی جلوگیری می‌کند. تاثیر trust و balance اختیاری است. معیار فرصت و موجودی محدود می‌مانند. اعتماد شاخص بازخورد است و شرط مستقل قفل یا برد نیست.

## شخصیت و تصویر

پالت و ظاهر هر نقش در characters.js است. renderer.character با این پالت و جهت حرکت، شخصیت را رسم می‌کند. برای تفاوت آناتومی یا sprite واردشده، فقط این بخش renderer را جایگزین کنید. برای یک نقش جدید باید starts، شخصیت، متن انتخاب نقش و منطق نقش اولیه در state.js نیز توسعه یابند.

## حرکت

movePlayer ورودی کیبورد را نرمال می‌کند تا حرکت مورب سریع‌تر نباشد. برخورد محوربه‌محور با حاشیه بدن اعمال می‌شود. findPath از A* هشت‌جهته روی شبکه محلی استفاده می‌کند و عبور مورب از گوشه بسته را رد می‌کند.

مسیریابی موانع ثابت را می‌شناسد؛ چرخ‌دستی پویا عمداً باید توسط بازیکن دیده و دور زده شود. کلیک دوباره یا کیبورد مسیر خودکار را لغو می‌کند. سرعت و شعاع برخورد در world.js و main.js متمرکزند.

در دسکتاپ کل ناحیه دیده می‌شود. در صفحه باریک دوربین کاراکتر را دنبال می‌کند. ورودی موس از مختصات صفحه به جهان تبدیل می‌شود و نقشه کوچک هم تبدیل خودش را دارد. DPR تا ۲ محدود شده و پس‌زمینه هر ناحیه cache می‌شود.

## تغییر قواعد و ذخیره‌ها

تغییر معنای exit یا حذف شناسه‌های قبلی می‌تواند replay را ناسازگار کند. در تغییر ناسازگار VERSION و کلید ذخیره را افزایش دهید یا migration صریح اضافه کنید. داده خراب با پیام قابل‌فهم به شروع تازه هدایت می‌شود؛ تا شروع بازی تازه خودکار بازنویسی نمی‌شود.

## کنترل کیفیت

- آزمون‌های graph، همه مسیرهای mouse، برخورد کیبورد و بازسازی ذخیره را اجرا کنید.
- یک در قفل‌شده، جمع‌آوری مدرک، عبور از در و یک پایان زودهنگام را در مرورگر آزمایش کنید.
- دوربین، مختصات کلیک و محل HUD را در اندازه هدف بررسی کنید.
- زمان خواندن dialog نباید زمان جهان یا حرکت چرخ‌دستی را جلو ببرد.
- بدون مجوز جدید هیچ اتصال به سامانه مبنا، سرویس خارجی یا دیتابیس اضافه نکنید.
